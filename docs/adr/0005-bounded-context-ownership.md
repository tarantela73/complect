---

## 2. Контекст

ERP «КОМПЛЕКТ» развёрнута как Modular Monolith в едином монорепозитории. Параллельная работа команд над доменами `contracts`, `finance`, `users` и `realtime` создаёт критический риск перекрёстного зацепления (High Coupling). Прямые импорты Django-моделей между доменами приводят к тому, что изменения в одном контексте ломают другой без предупреждения.

---

## 3. Решение

Установить матрицу владения и три закона кросс-доменных взаимодействий.

### Матрица владения контекстами

| Контекст                                         | Команда-владелец            | Ответственность                                           |
| ------------------------------------------------ | --------------------------- | --------------------------------------------------------- |
| `apps/users`, `apps/workflows`                   | Core Platform Team          | MFA, RBAC, JWT, Device Fingerprint, FSM-движок           |
| `apps/contracts`, `apps/contragents`             | Legal Tech Feature Team     | Жизненный цикл договоров, PII, ClamAV, Legal Hold        |
| `apps/finance`, `apps/analytics`, `apps/integration` | FinTech & Integrations Team | Ledger, дебиторка, BFF-аналитика, ACL-маппер 1С      |
| `apps/realtime`, `apps/chat`, `apps/notifications` | Realtime Infrastructure Team | Redis Streams, WebSocket, Event Replay, LiveKit WebRTC |

### Закон 1 — Полная изоляция моделей

Прямой импорт Django-моделей из чужого домена **категорически запрещён**.

```python
# ЗАПРЕЩЕНО — вызывает падение CI/CD Quality Gate
from apps.finance.models.ledger import LedgerTransaction  # внутри apps/contracts/
```

### Закон 2 — Internal SDK через typing.Protocol

Межмодульное синхронное общение — исключительно через абстрактные контракты (`typing.Protocol`) в `apps/common/contracts/`. Домен-потребитель импортирует только Protocol; реализация регистрируется в контейнере зависимостей при старте приложения.

### Закон 3 — Асинхронная развязка через Outbox

Если домену нужно уведомить систему об изменении своего состояния — он выбрасывает иммутабельное `@dataclass(slots=True, frozen=True)` событие в Transactional Outbox. Другие домены подписываются асинхронно через Celery-очереди.

---

## 4. Рассмотренные альтернативы

| Альтернатива              | Причина отказа                                                       |
| ------------------------- | -------------------------------------------------------------------- |
| Прямые кросс-импорты      | Спагетти-зависимости; невозможность независимого деплоя контекстов. |
| Shared Database Schema    | Любое изменение схемы затрагивает все домены одновременно.          |

---

## 5. Последствия

### Плюсы

- Любой контекст можно вырезать и превратить в микросервис без изменения кода других доменов.
- CI/CD Quality Gate автоматически блокирует нарушения.

### Минусы

- Разработчикам нужно писать дополнительные Protocol-интерфейсы и DTO маппинга на границах доменов.

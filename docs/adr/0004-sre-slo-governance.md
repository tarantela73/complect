# 0004 — SRE SLO Governance и автоматическое управление Error Budget

## 1. Статус

| Поле     | Значение                                            |
| -------- | --------------------------------------------------- |
| Статус   | APPROVED                                            |
| Дата     | 2026-05-24                                          |
| Владелец | SRE Infrastructure Core Lead / DevOps Engineer      |

---

## 2. Контекст

ERP «КОМПЛЕКТ» обрабатывает критические бизнес-процессы холдинга — финансы, юридический контур, ГИС-данные. Задержка репликации между PostgreSQL Primary и Replica или зависание задач в Celery-очереди `antivirus` приводят к тому, что менеджеры видят устаревшие данные, а файлы зависают в статусе `VIRUS_SCANNING`, нарушая SLA платформы.

---

## 3. Решение

Зафиксировать матрицу SLA/SLO и автоматические триггеры реагирования.

### Матрица пороговых значений

| Метрика              | SLO    | p95      | p99      |
| -------------------- | ------ | -------- | -------- |
| REST API             | 99.9%  | < 150 ms | < 300 ms |
| Dashboard BFF        | 99.0%  | < 500 ms | —        |
| Search               | —      | < 200 ms | —        |
| Queue Latency        | —      | < 5 с    | —        |
| Replica Lag          | —      | < 1000 ms | —       |

### Автоматические триггеры

#### Replica Lag > 1 с в течение 30 с

Kong автоматически активирует Sticky Routing для 100% читающих запросов, переключая трафик на Primary. Replica изолируется до восстановления синхронизации.

#### Queue Latency > 15 с

Включается kill-switch: тяжёлые фоновые задачи (генерация PDF-отчётов) блокируются в API, освобождая ресурсы под финансовые транзакции и валидацию файлов.

#### Error Budget = 0% (скользящие 30 дней)

Включается тотальный Feature Freeze. CI/CD блокирует деплой продуктовых фич. Пропускаются только PR, помеченные командой SRE как `[RELIABILITY-FIX]`.

---

## 4. Рассмотренные альтернативы

| Альтернатива               | Причина отказа                                                       |
| -------------------------- | -------------------------------------------------------------------- |
| Ручное переключение трафика | Человеческий фактор: реакция запаздывает, Error Budget сгорает.     |
| Alerting без автоматики    | Только уведомляет, не защищает платформу в реальном времени.        |

---

## 5. Последствия

### Плюсы

- Нулевой риск каскадного падения СУБД под нагрузкой.
- Система защищает сама себя на уровне сетевого шлюза.
- Бизнес получает гарантию надёжности через контракт SLA.

### Минусы

- При авариях инфраструктуры выкатка продуктовых фич полностью парализуется до устранения деградации.

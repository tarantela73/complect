## 2.CONTEXT
Архитектура ERP «КОМПЛЕКТ» построена на жестком разделении CQRS и BFF. Фронтенд полностью зависит от автогенерируемого TS SDK. Ручное изменение Pydantic DTO схем бэкенда (schemas/) без контроля обратной совместимости приводит к незаметному падению TypeScript компиляции на фронтенде во время релиза, выжигая Error Budget REST API (SLO 99.9%) [10.3]
## .3. DECISION & ENGINEERING LAWВвести политику Заморозки схемы OpenAPI (Schema Freeze Policy) для живой мажорной версии /api/v1/:
1. Запрет на удаление: Запрещено удалять эндпоинты, методы, query-параметры или существующие поля из Pydantic-схем ответов (Response DTO).
2. Запрет на мутацию типов: Запрещено менять тип существующих полей (например, uuid.UUID на str).
3. Запрет на обязательность: Запрещено добавлять новые обязательные (required) поля во входящие Pydantic-схемы (Request DTO) или новые обязательные Query/Header параметры без дефолтных значений.
4. Разрешено: Добавлять новые эндпоинты, добавлять новые опциональные (nullable) поля в ответы.
Любое деструктивное изменение обязано выноситься в изолированный роут новой мажорной версии /api/v2/ и проходить через 6-месячное Migration Window [6.4 ТЗ].

## 4. CONSEQUENCES
Pros: На фронтенде полностью исключен краш рантайма из-за изменений бэкенда. Контракт железобетонен.
Cons: Бэкенд-разработчики не могут «по-быстрому» переименовать кривое поле в базе или DTO. Требуется строгая дисциплина.

# SRE SLO Governance & Automated Error Budget Enforcement.

## 1. STATUSС
Cтатус: APPROVED FOR IMPLEMENTATION
Дата: 2026-05-24
Владелец: SRE Infrastructure Core Lead / DevOps Engineer
## 2. CONTEXT
ERP «КОМПЛЕКТ» обрабатывает критические бизнес-процессы холдинга (финансы, юридический контур, ГИС-данные). Задержка репликации между PostgreSQL Primary (Москва) и Replica (Санкт-Петербург) [Раздел 3 ТЗ] или провисание задач в Celery очереди antivirus приводят к тому, что менеджеры видят устаревшие данные, а файлы зависают в статусе VIRUS_SCANNING [5.4], нарушая общие SLA платформы.
## 3. DECISION & SRE LAWS
Намертво зафиксировать Матрицу SLA/SLO Метрик и автоматические триггеры реагирования:

А. Матрица пороговых значений (SLA Thresholds)REST API SLO (99.9%): Время ответа p95 < 150ms, p99 < 300ms. Ошибки 5xx — жесткий инцидент.
Dashboard BFF SLO (99.0%): Время ответа комбо-запроса Шефа p95 < 500ms.
Queue Latency SLA: Время нахождения задачи в Celery очередях (finance, antivirus) до момента подхвата воркером — строго < 5 секунд.
Replica Lag Budget: Задержка синхронизации данных между мастером и репликой (pg_replication_lag) — строго < 1000 миллисекунд (1 секунда).

Б. Автоматическое управление Бюджетом Ошибок (Error Budget Law)
Если pg_replication_lag > 1с в течение 30 секунд: API шлюз Kong автоматически активирует Sticky Routing [Пункт 5] для 100% читающих запросов, принудительно переключая трафик с упавшей реплики на Primary мастер. postgres_replica изолируется до восстановления синхронизации.
Если Queue Latency > 15 секунд: Включается kill-switch операционных флагов [ADR 0007]. Тяжелые фоновые задачи (генерация PDF-отчетов WeasyPrint) временно блокируются в API, освобождая ресурсы под валидацию файлов и финансовые транзакции.
Если Error Budget = 0% за скользящие 30 дней: Включается тотальный Freeze Feature Development [10.4]. Пайплайн CI/CD намертво блокирует деплой продуктовых фич, пропуская только те PR, которые помечены SRE-командой как [RELIABILITY-FIX].## 4. CONSEQUENCES
Pros: Нулевой риск каскадного падения СУБД. Система защищает сама себя от перегрузок на уровне сетевого шлюза. Бизнес гарантированно получает надежный софт.
Cons: При авариях инфраструктуры выкатка продуктовых фич полностью парализуется до тех пор, пока инженеры не починят задержки очередей или репликацию.

## Цель

Связать объект (`SupplyObject`) с его кадастровым участком: сохранить кадастровый номер, граничный полигон и список пересекающихся ЗОУИТ-зон. Данные отображать на 360°-карточке объекта.

## Контекст

Уже реализовано (не трогаем):
- Поиск по кадастровому номеру: `pkk_client.py` → `map_search` API → `MapSearchBar` + `CadastralHighlight`
- Кадастровая сетка и ЗОУИТ-тайлы: `PKK_TILES` / `OPENINFRA_TILES` (XYZ, не WMS)
- PostGIS: `SupplyObject.location` (Point) и `SupplyObject.boundary` (Polygon) — есть, но `boundary` не заполняется из ПКК

`rosreestr2coord` — **не нужна**. Наш `pkk_client.py` бьёт тот же endpoint (`pkk.rosreestr.ru/api/features/1`) и уже работает в проде.

## Пользовательский сценарий

1. Менеджер открывает карточку объекта 360° → вкладка/блок "Карта / ГИС"
2. Нажимает "Найти участок" → поиск по кадастровому номеру (через существующий `MapSearchBar`)
3. Выбирает результат → на карте подсвечивается контур участка
4. Нажимает "Привязать участок" → система сохраняет кадастровый номер + полигон + ЗОУИТ-зоны
5. Блок показывает: кадастровый номер, площадь по данным ПКК, список ЗОУИТ (типы, ограничения)

Альтернативно: поле кадастрового номера в форме редактирования объекта — ввёл вручную → автоматически запрашивает ПКК и сохраняет данные.

## Требования

### Модель (SupplyObject)

- Добавить `cadastral_number: CharField(max_length=30, blank=True)` — формат `77:01:0001001:1`
- `boundary` уже есть (PolygonField) — заполнять при привязке из ПКК
- Добавить `cadastral_area_sqm: DecimalField(null=True)` — площадь из атрибутов ПКК (`attrs.area_value`)
- Добавить `zouit_zones: JSONField(default=list)` — список зон: `[{type_name, restriction, description}]`

### Backend

- `pkk_client.py`: расширить `search_cadastre` — возвращать также `area_sqm` из `attrs.area_value`
- Новая функция `fetch_zouit_zones(cadastral_number)` — запрос к ПКК API `features/10` (тип ЗОУИТ, пересечение по bbox/кадастровому контуру)
- Сервис `CadastralBindingService.bind(object_id, cadastral_number)`:
  1. Вызывает `search_cadastre` → получает geometry + area
  2. Вызывает `fetch_zouit_zones` → получает список зон
  3. Атомарно сохраняет всё в объект через `EnterpriseSreRepository.atomic_cas_update()`
- Новый эндпоинт `PATCH /api/v1/objects/{object_id}/cadastral/` (требует `objects.write`)

### Frontend

- В форме редактирования объекта: поле "Кадастровый номер" с кнопкой "Найти"
- На 360°-карточке: GIS-блок — мини-карта с контуром участка, кадастровый номер, площадь, список ЗОУИТ-зон
- Мини-карта использует `MapView` с `showCadastral=true`, `showInfra=true`, `highlightGeometry` из `boundary`

## Границы

**В скоупе:**
- Привязка одного кадастрового участка к объекту
- Сохранение boundary, area, ЗОУИТ-зон
- Отображение в 360°-карточке

**Не в скоупе:**
- Несколько кадастровых участков на один объект
- Синхронизация с Росреестром (актуализация данных по расписанию)
- Полигоны ЗОУИТ в PostGIS (только JSON-список зон, не геометрия)
- Экспорт кадастровых данных в PDF/выписку

## Риски

- ПКК API нестабилен (известны периодические блокировки — см. предыдущий опыт с PKK tiles). Привязка должна быть graceful: не удалось — показываем ошибку, не ломаем объект.
- ЗОУИТ API (`features/10`) задокументирован неофициально — нужно протестировать на реальных участках с известными зонами.
- `area_value` в атрибутах ПКК — не всегда присутствует для всех типов объектов.

## Критерии готовности

- `cadastral_number` сохраняется и отображается на 360°-карточке
- `boundary` полигон виден на мини-карте в карточке объекта
- ЗОУИТ-зоны отображаются списком (пустой список если нет зон — это норма)
- При недоступности ПКК API: объект сохраняется только с кадастровым номером, остальные поля пустые (не ошибка)
- Миграция по Expand & Contract (ADR-0002): все новые поля nullable на релиз N

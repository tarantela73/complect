# Сбалансированная очистка skills

## Цель

Устранить дублирование источников Superpowers и сохранить строгие инженерные
проверки без обязательного многоэтапного процесса для небольших задач.

## Текущее состояние

- Системные Codex skills находятся в `~/.codex/skills/.system`.
- Superpowers доступен через общий symlink
  `~/.agents/skills/superpowers -> ~/.superpowers/skills`.
- Репозиторий `~/.superpowers` отстаёт от upstream и содержит пользовательский
  untracked-файл `update.sh`, который необходимо сохранить.
- В кеше Codex находится ещё одна копия Superpowers 5.1.3. Кеш не должен быть
  постоянным источником skills.

## Канонический источник

Единственным постоянным источником Superpowers остаётся git-репозиторий
`~/.superpowers`. Перед переключением экспорта он обновляется обычным fast-forward
или rebase без удаления пользовательских файлов.

Системные Codex skills и кеш Codex не изменяются.

## Экспортируемый набор

В `~/.agents/skills/` создаются отдельные symlink на следующие skills:

- `systematic-debugging`;
- `test-driven-development`;
- `verification-before-completion`;
- `receiving-code-review`;
- `requesting-code-review`;
- `writing-plans`;
- `executing-plans`;
- `finishing-a-development-branch`;
- `using-git-worktrees`.

Общий symlink `superpowers` удаляется только после проверки источника и
сохраняется как резервная копия пути до успешной верификации нового набора.

## Исключённый набор

Следующие skills не экспортируются:

- `using-superpowers` — принудительно перехватывает каждый ответ;
- `brainstorming` — вводит обязательные spec/commit gates для небольших задач;
- `dispatching-parallel-agents` и `subagent-driven-development` — не
  соответствуют действующему запрету на автоматическую делегацию;
- `writing-skills` — используется только при разработке skills и перекрывается
  системным `skill-creator`.

Исключение означает отсутствие автоматического обнаружения, но исходные файлы
остаются в `~/.superpowers` и могут быть возвращены отдельным symlink.

## Безопасность изменений

- Не удалять `~/.superpowers`, системные skills или кеш Codex.
- Не изменять содержимое сторонних `SKILL.md`.
- Сохранить `~/.superpowers/update.sh`.
- Перед заменой проверить, что каждый целевой `SKILL.md` существует.
- При ошибке восстановления вернуть общий symlink.
- Запросить разрешение на запись вне workspace и сетевое обновление.

## Проверка

После переключения:

1. проверить разрешение каждого symlink до существующего `SKILL.md`;
2. убедиться, что в `~/.agents/skills` присутствуют ровно девять выбранных
   Superpowers skills;
3. убедиться, что исключённые skills не экспортируются;
4. проверить чистоту tracked-файлов репозитория `~/.superpowers` и сохранность
   `update.sh`;
5. открыть новую сессию Codex и сверить фактически обнаруженный список skills.

Последний пункт нельзя доказать в уже запущенной сессии, поскольку перечень
skills формируется при её старте.

# Complect: применение полного Harness Creator

Дата: 2026-10-11. Область: рабочий цикл агента, инструкции, состояние,
доказательства завершения и безопасный запуск служебных проверок.

До изменения Complect уже имел root/scoped инструкции, ADR, маршрутизацию
скиллов, Makefile и правила изоляции тестов. Недоставало общего реестра текущей
задачи, сохранённого handoff и автоматической проверки её доказательств.
Исходные инструкции и посторонняя рабочая правка сохранены.

## Результат

| Подсистема | Реализация | Проверка |
| --- | --- | --- |
| Инструкции | Короткая маршрутизация в AGENTS.md, локальный полный скилл и harness.md | Локальные ссылки, происхождение и SHA-256 |
| Состояние | feature_list.json, progress.md | Статусы, ID, зависимости, одна активная задача |
| Проверки | init.sh, make harness-check, запись фактического запуска | Одноразовые контейнеры Python/Node, exit code и логи |
| Границы | Файлы и критерии в feature_list.json | Покрытие файлов доказательствами, hash freshness |
| Жизненный цикл | session-handoff.md, начало/завершение по harness.md | Состояние и путь возобновления доступны локально |

Полный скилл включает 26 исходных файлов и лицензию. Изменённые файлы
отделены от upstream в harness-skill-provenance.json. Источник закреплён
SHA-256 скачанного архива; upstream commit отдельно не проверялся.
Все семь справочных разделов применены с учётом приоритета Complect/Codex.
Примеры другого runtime не стали правилами авторизации или архитектуры ERP.

Исправлены ложный успех без тестов, принятие pytest exit 5, выход через
`--agent-file`, запись через симлинк, повторное выполнение `$()` в диагностике,
отсутствие корректной рабочей директории и `pipefail`, неверные статусы,
дубликаты/циклы зависимостей, закрытие без доказательств и некорректные пороги
оценки. Benchmark self-check теперь выполняет реальную проверку сгенерированного
примера; eval coverage явно обозначено как metadata, выполнение eval — NOT_RUN.

## Доказательства

18 Python-тестов и 21 Node-тест выполнены в Docker: PASS, без пропусков.
Команда `python3 -B infra/scripts/agent_harness.py --record` сохраняет реальный
stdout/stderr, код, cwd, run ID, SHA-256 логов и исходников. Финальное успешное
доказательство и его источники перечислены в feature_list.json. Неуспешный
промежуточный запуск сохранён отдельно и не учитывается как PASS.

Образы закреплены digest, сеть отключена, root filesystem read-only, capabilities
сняты. Отдельный тест проверяет отсутствие Git, ERP, secrets, bind mounts,
volumes и Docker socket в передаваемом архиве/аргументах запуска.
Полный набор файлов скилла и их хеши проверяет provenance gate.

## Ограничения

ERP_ACCEPTANCE: NOT_RUN. Изменение служебного комплекта не подтверждает состояние
продуктовых тестов, historical recovery, production readiness или улучшение
эффективности реальных агентских сессий. Для них действуют прежние матрицы,
изоляция и release gates. Локальный receipt подтверждает записанный запуск и
целостность источников; он не является защищённой от подделки аттестацией.

CodeGraph использован для impact pass. Repowise не дал покрытия этих новых
файлов; его старый индекс не принят за доказательство. Независимое ревью
проверило инструменты, область работы и ограничения отчёта.

## Следующий запуск

Из корня выполнить `./init.sh` или `make harness-check`. Для новой задачи
обновить реестр, выбрать обязательные руководства и проверки по её поведению,
затем сохранить реальный результат и handoff. Документирование бизнес-результата
требует соответствующих Docker/PostgreSQL/API/browser проверок.

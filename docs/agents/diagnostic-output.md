# Краткая диагностика агента

Загружай этот процесс при штатном наблюдении, чтении большого dirty status,
нескольких разделов документов или разборе конкретной ошибки. Команды проверок
запускай через [verification runner](verification-runner.md); этот модуль только
представляет результаты и не заменяет runner или валидатор доказательств.

## Штатное наблюдение

Выводи попытку, стадию, статус, счётчики, исходный exit и пути к artifacts.
Для qualification/recovery выбирай `--summary-output /absolute/new-file.json`.
Полные native result/receipts и их stdout/stderr остаются источником проверки;
summary создаёт отдельную очищенную копию. Флаг должен поддерживаться выбранным
commit qualification. Отказ `SUMMARY_MODE_UNSUPPORTED_COMMIT` требует выбрать
поддерживаемый источник, а не запускать сборку с неподтверждённым режимом.

Artifact должен быть новым обычным файлом с существующим родительским каталогом.
Внутри checkout используй `.dev/test-artifacts/`, передавай `--source-root` для
проверки границы записи artifact. Входные файлы выбираются явно через `--input`
или `--section`; `--source-root` не ограничивает область чтения. Ссылки и
перезапись отвергаются. Файлы создаются с mode0600.
Передай имена переменных известных секретов повторяемым `--redact-env NAME`;
значения не включай в argv. Это точечная очистка известных значений: до чтения
проверь применимые правила PII/секретов и при необходимости подготовь очищенный
источник. Native proof сохраняет действующий контракт очистки своего producer.

## Полный status и пути задачи

При старте сохраняй полный статус через helper; в контекст передавай его сводку
и только согласованные пути задачи. При неизвестном scope сначала получи счётчики,
затем повтори с нужными `--scope` и новым artifact. Полный status хранится в
porcelain-v1 `-z`: NUL разделяет записи, rename/copy содержит также исходный путь.
Helper использует `GIT_OPTIONAL_LOCKS=0`; статус не меняет индекс.

```sh
python3 -B -m infra.scripts.diagnostic_output status \
  --root "$PWD" --source-root "$PWD" \
  --scope infra/scripts/diagnostic_output.py --scope docs/agents/diagnostic-output.md \
  --artifact "$PWD/.dev/test-artifacts/task/status-01.bin"
```

## Разделы документов и общий бюджет

Выбирай точные уникальные заголовки Markdown. Перед независимыми чтениями задай
один бюджет на весь ответ: собери разделы одним вызовом `documents` либо результаты
в `DiagnosticBatch`, затем один раз вызови `write`. Несколько отдельных выводов
по 4 КиБ не считаются общим ограничением. Для обязательных инструкций последовательно
дочитай нужные части из полного источника; сначала ограничь набор разделов,
а не достоверность проверки.

```sh
python3 -B -m infra.scripts.diagnostic_output documents --source-root "$PWD" \
  --section docs/agents/harness.md 'Переход к итоговой проверке' \
  --section docs/agents/ci-auditor.md 'Сохранение точки продолжения' \
  --artifact "$PWD/.dev/test-artifacts/task/documents-01.txt"
```

## Конкретная ошибка

Автоматическое представление ограничено одновременно 20 строками и 4096 байтами
UTF-8, включая metadata и `[TRUNCATED]`. Рядом сохраняются путь и SHA-256 полного
очищенного artifact. Для JSON выбирай конкретное поле через JSON Pointer;
полный очищенный JSON сохраняется целиком. Для журнала показывается хвост.

```sh
python3 -B -m infra.scripts.diagnostic_output error --source-root "$PWD" \
  --input /absolute/cleaned-result.json --json-pointer /primary_error \
  --artifact "$PWD/.dev/test-artifacts/task/error-01.json"
```

Усечение означает, что видна только часть данных. Найди нужный фрагмент в полном
источнике отдельным адресным чтением либо явно укажи предел проверки. Отсутствие
текста в сводке не доказывает отсутствие поведения, проверки или ошибки.
Сверяй исходный exit и полные receipts отдельно: успех представления не означает
PASS проверяемой команды. Ошибка представления сохраняет первичный nonzero exit;
при первичном успехе host summary возвращает 2.

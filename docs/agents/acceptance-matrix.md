# Проверяемая матрица критериев

Матрица #75 проверяется read-only публичной командой `python3 -B -m infra.scripts.acceptance_matrix`. Команды из входных JSON не исполняются. Входы — independently pinned requirements, отдельно pinned matrix и явно выбранный evidence root. Передай `--requirements`, `--requirements-sha256`, `--matrix`, `--matrix-sha256`, `--root`; хеши берутся из родительского индекса, а не из перепроверяемой матрицы.

## Требования до исполнения

Формат требований — `complect-acceptance-matrix-requirements-v1`. Непустой `sources` содержит относительные пути исходных требований и SHA-256. Непустой `criteria` фиксирует по каждому требованию `issue` (положительное целое), `id` вида issue-N, точную непустую `quote`, `source` из sources, `source_identity`, `identity_pointer` и непустую карту `facts`.

Цитата должна присутствовать в аутентифицированном исходном документе. `identity_pointer` — JSON Pointer к ожидаемой source identity в evidence. `source_identity` задаётся родителем независимо от будущего отчёта. `facts` задаёт JSON Pointer → ожидаемое значение проверяемых фактов. Например, успешная команда требует status PASS и exit0; проверка ожидаемого отказа может заранее требовать другой первичный verdict/exit. Факты не выводятся из самого полученного evidence. JSON Pointer поддерживает RFC6901 escapes и индексы массивов; булевы false и целое0 не равны.

Хеш файла требований закрепляется до исполнения. Изменение перечня, цитат, identity или ожидаемых фактов требует нового родительского файла/pin и пересмотра применимых результатов. JSON с дублирующимися ключами или нечисловыми константами NaN/Infinity отвергается.

## Матрица после исполнения

Формат — `complect-acceptance-matrix-v1`, `requirements_sha256` равен родительскому pin. Каждая запись `rows` содержит `issue`, `id`, точную `quote`, `status`, `evidence` с относительным path и SHA-256. Каждому критерию соответствует ровно одна строка. Пропуски, повторы, неизвестные ID и диапазоны вместо отдельных ID отвергаются. Свежий matrix SHA-256 координатор закрепляет отдельно от исполнителя до проверки.

Evidence — JSON-документ с проверяемыми identity и фактами по родительским указателям. Проверяются полные хеши оригинальных документов, затем поля identity/facts. Абсолютные пути, переход через родителя, symlinks, специальные файлы, повреждённые и отсутствующие JSON не принимаются. Ограничение одного документа — 1 МиБ. Исходные receipts не переписываются; ссылаться можно на существующий согласованный JSON через подходящие родительские JSON Pointer. Это не заменяет его producer-specific приёмку.

## Результат

Результат `complect-acceptance-matrix-result-v1` разделяет `coverage`, `integrity`, `behavior` и общий `status`. Полная структура с FAIL/PARTIAL/BLOCKED/NOT_RUN/FAIL_BASELINE либо BLOCKED_* у критерия сохраняет неположительный behavior. Общий PASS требует полного покрытия, целостных доказательств, совпавших identity/facts и PASS каждой строки. Unknown/malformed статусы не принимаются.

Exit0 — общий PASS; exit1 — неполное покрытие или невыполненный критерий; exit2 — иная ошибка обязательных входов/evidence. Хеши и совпадение фактов не являются подписанной аттестацией: независимое Standards/Spec review отдельно оценивает, доказывают ли факты смысл требования. Полнота матрицы не повышает непринятый producer receipt и не заменяет review.

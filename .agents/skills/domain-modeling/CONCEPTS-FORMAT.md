# Complect glossary format

Extend the existing [CONCEPTS.md](../../../CONCEPTS.md) structure in place:
context/domain headings, named concepts and concise definitions with meaningful
lifecycle or relationship distinctions. Preserve accepted terminology.

Record what a term means; include discriminating edge cases when needed. Keep
implementation procedures, rollout instructions and architectural trade-offs in
their existing authoritative documents. Do not reformat the glossary wholesale,
create another glossary, or infer the number of bounded contexts from the number
of documentation files.
